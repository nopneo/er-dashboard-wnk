1ER Dashboard คืออะไร

เว็บแอปที่ดึงข้อมูลห้องฉุกเฉินจากฐานข้อมูล HOSxP แบบสด แล้วแสดงเป็นอินโฟกราฟิกหน้าเดียว 18 บล็อก หัวหน้าห้องฉุกเฉินและผู้บริหารเปิดดูได้ทั้งบนคอมพิวเตอร์และมือถือ กรองตามเวรได้ และกดส่งออกเป็น JPG / PNG / PDF ไปใช้ในการประชุมได้ทันที

  • อ่านอย่างเดียว — ไม่เขียน ไม่แก้ข้อมูลใน HOSxP
  • ไม่มีข้อมูลรายบุคคล — แสดงเฉพาะตัวเลขรวม ไม่มี HN / ชื่อผู้ป่วย
  • ไม่ต้องคีย์ข้อมูลเพิ่ม — ใช้ข้อมูลที่ ER บันทึกใน HOSxP อยู่แล้ว
  • ทำงานในโรงพยาบาล — ไม่ส่งข้อมูลไปเซิร์ฟเวอร์ภายนอก
  • ใช้ฟรี — โอเพนซอร์ส ใบอนุญาต MIT

2สิ่งที่ต้องเตรียม

รายการข้อกำหนด
เครื่องเซิร์ฟเวอร์Linux (AlmaLinux / Rocky / RHEL 9, Ubuntu 22.04 ขึ้นไป) หรือ Windows 10/11/Server · CPU 2 core, RAM 2 GB, พื้นที่ว่าง 2 GB (ใช้ร่วมกับเครื่องที่มีอยู่แล้วได้)
Python3.9 ขึ้นไป
ฐานข้อมูล HOSxPMariaDB / MySQL ที่เครื่องนี้ต่อถึงได้ พอร์ต 3306 · แนะนำให้ต่อเครื่อง Slave / Replica ไม่ใช่ฐานหลักที่ใช้ให้บริการ
การบันทึกของ ERห้องฉุกเฉินใช้ระบบ ER ของ HOSxP (er_regist มีเวลาเข้า ER) และลงระดับความเร่งด่วน
บัญชีฐานข้อมูลสิทธิ์ SELECT อย่างเดียว (หัวข้อ 3)
เบราว์เซอร์บนเซิร์ฟเวอร์Chromium / Chrome / Edge — เฉพาะเมื่อต้องการปุ่มส่งออก
ไฟล์ชุดติดตั้ง — ดาวน์โหลด er_dashboard-{{VERSION}}.zip จาก github.com/nopneo/er-dashboard-wnk/releases ภายในมีโปรแกรม คู่มือนี้ INSTALL.md SECURITY.md และ .env.example — ไม่มีรหัสผ่านหรือข้อมูลของโรงพยาบาลใดติดมา

3สร้างบัญชีฐานข้อมูลอ่านอย่างเดียว

ล็อกอินฐานข้อมูล HOSxP ด้วยบัญชีผู้ดูแล แล้วรัน (เปลี่ยน IP เป็นเครื่องที่ติดตั้งแดชบอร์ด):

CREATE USER 'er_ro'@'192.168.1.50' IDENTIFIED BY '<รหัสผ่านยาวอย่างน้อย 16 ตัว>';
GRANT SELECT ON hos.* TO 'er_ro'@'192.168.1.50';
ห้ามใช้บัญชีที่เขียนข้อมูลได้ — แม้แอปจะตั้ง session เป็น READ ONLY ให้อีกชั้น บัญชีควรมีสิทธิ์ SELECT อย่างเดียวและจำกัด host เสมอ

4ติดตั้งบน Linux (แนะนำ)

  1. แตกไฟล์และติดตั้งไลบรารี 
    unzip er_dashboard-{{VERSION}}.zip -d /opt && cd /opt/er_dashboard
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
  2. สร้างไฟล์ค่าตั้ง แล้วใส่ DB_HOST DB_USER DB_PASS 
    cp .env.example .env && nano .env
  3. ทดลองรัน แล้วเปิด http://<IP เครื่อง>:6200/ 
    .venv/bin/python app.py      # Ctrl+C เพื่อหยุด
  4. สร้างผู้ใช้สำหรับบริการ (ไม่ใช้ root) และตั้งสิทธิ์ไฟล์ 
    useradd -r -s /sbin/nologin erdash
chown -R root:root /opt/er_dashboard
chown root:erdash /opt/er_dashboard/.env && chmod 640 /opt/er_dashboard/.env
  5. สร้างไฟล์บริการ /etc/systemd/system/er-dashboard.service 
    [Unit]
Description=ER Dashboard
After=network.target

[Service]
User=erdash
Group=erdash
WorkingDirectory=/opt/er_dashboard
ExecStart=/opt/er_dashboard/.venv/bin/gunicorn --bind 0.0.0.0:6200 --workers 3 --timeout 120 app:app
Restart=always
Environment=HOME=/var/lib/erdash
StateDirectory=erdash
NoNewPrivileges=true
PrivateTmp=true
ProtectSystem=strict
ProtectHome=true

[Install]
WantedBy=multi-user.target
  6. เปิดบริการ 
    systemctl daemon-reload && systemctl enable --now er-dashboard
systemctl status er-dashboard
ปุ่มส่งออก — ติดตั้ง Chromium (AlmaLinux: dnf install chromium-headless) ถ้าไม่ต้องการ ตั้ง ER_EXPORT=0 ใน .env เพื่อซ่อนปุ่ม

5ติดตั้งบน Windows

python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
copy .env.example .env  &  notepad .env
.venv\Scripts\waitress-serve --listen=0.0.0.0:6200 app:app

ต้องการให้เปิดเองเมื่อเปิดเครื่อง ใช้ Task Scheduler หรือ NSSM ห่อคำสั่งสุดท้ายเป็นบริการ

6ติดตั้งด้วย Docker

docker build -t er-dashboard .                          # ไม่มีปุ่มส่งออก (image เล็ก)
docker build --target export -t er-dashboard-export .   # มี chromium
docker run -d -p 6200:8080 --env-file .env --restart unless-stopped er-dashboard

7ตั้งค่า (.env)

ค่าความหมาย
DB_HOST DB_PORT DB_NAME DB_USER DB_PASSฐานข้อมูล HOSxP (บัญชีอ่านอย่างเดียว)
PORTพอร์ตของแอป (6200)
ER_HOSPITAL_NAME / _ENชื่อโรงพยาบาล (ไม่ใส่ = อ่านจาก opdconfig)
ER_CONTACTช่องทางติดต่อท้ายหน้า
ER_DEPCODEรหัสแผนก ER (ค่าเริ่มต้น 011)
ER_NOT_DEPCODESรหัสที่ไม่ใช่แผนกจริง (ค่าเริ่มต้น 999 = กลับบ้าน)
ER_ST_DOCTOR_COLคอลัมน์ service_time ที่ ER กด "เริ่มตรวจ" (ค่าเริ่มต้น service5)
ER_RED_MAX_MINเกณฑ์ผู้ป่วยระดับ 1 อยู่ใน ER (60 นาที)
ER_MCI_MIN / ER_MCI_WINDOWอุบัติเหตุหมู่: ≥ 5 ราย ภายใน 60 นาที
ER_BOARDING_MINเข้า ER → Admit/Refer เกินกี่นาทีถือว่านาน (120)
ER_MAX_DAYS / ER_CACHE_TTL / ER_DB_TIMEOUTช่วงวันที่สูงสุด (366) · อายุแคช (120 วิ) · timeout ต่อคำสั่ง (60 วิ)
ER_EXPORT0 = ปิดปุ่มส่งออก
ER_NP_START / ER_NP_ENDช่วงเวลารายงานพยาบาลตรวจแทนแพทย์ (16:00 / 20:00)
ER_NURSE_PROVIDER_TYPESdoctor.provider_type_code ที่นับเป็นพยาบาล (ค่าเริ่มต้น 03)
ER_NP_PASS_HASH / ER_SECRET_KEYhash ของรหัสเข้าดูรายงานพยาบาล · key ของ cookie เข้าระบบ (หัวข้อ 8.4)
ER_NP_LOGIN_HOURS / ER_NP_MAX_DAYSอยู่ในระบบได้กี่ชั่วโมง (12) · ช่วงวันที่ยาวสุดของรายงาน (1827 = 5 ปี)

โลโก้และภาพพื้นหลัง — วาง static/img/hospital_logo.png (สี่เหลี่ยมจัตุรัส) และ static/img/hero.jpg (แนวนอน) แล้วรีสตาร์ตบริการ

8ตรวจข้อมูลก่อนใช้ / ปรับให้ตรงกับการบันทึก

ก่อนนำตัวเลขไปใช้ — รหัสใน HOSxP ของแต่ละโรงพยาบาลไม่เหมือนกัน (ประเภทการมา EMS / Refer / นัด, การจำหน่าย, ประเภทผู้ป่วย, แผนก ER, คอลัมน์เริ่มตรวจ) ถ้าไม่ตรง ตัวเลขเพี้ยนโดยไม่มีข้อความเตือน แดชบอร์ดจึงแสดงแถบ “ตัวเลขยังไม่ได้ตรวจกับข้อมูลของโรงพยาบาลนี้” จนกว่าจะตรวจตามข้อ 8.1–8.2

8.1 ตรวจความพร้อม — setup_check.py

.venv/bin/python setup_check.py        # Windows: .venv\Scripts\python setup_check.py

ตรวจ Python ไลบรารี เขตเวลา Chrome การเชื่อมต่อฐานข้อมูล สิทธิ์อ่านอย่างเดียว ตารางที่ใช้ ภาษาไทย visit ER ล่าสุด และรหัสของโรงพยาบาล · ✔ ผ่าน · ⚠ ควรตรวจ · ✘ ต้องแก้ก่อนใช้ · แนบผลนี้ทุกครั้งที่แจ้งปัญหา

8.2 ตรวจข้อมูลก่อนใช้ — หน้า /check

เปิด http://<เซิร์ฟเวอร์>:6200/check จากเครื่องในโรงพยาบาล (แสดงเฉพาะจำนวนนับ) บนสุดสรุปเรื่องที่ควรแก้ ตารางแรกเทียบรหัสที่แอปใช้กับชื่อรหัสและ % ของ visit ER ที่พบจริง พร้อมค่าที่ควรตั้ง เช่น ER_EMS_FR_CODES=06,07 · ใส่ใน .env → รีสตาร์ต → เปิดหน้านี้ใหม่ · ทดลองใช้คู่รายงานเดิม 1–2 สัปดาห์ ตัวเลขตรงแล้วตั้ง ER_DATA_AUDITED=1 (ซ่อนแถบเตือน)

8.3 เวลาพบแพทย์

หลายโรงพยาบาลกดปุ่ม "เริ่มตรวจ" ตอนเปิดชาร์ตลงบันทึก ซึ่งช้ากว่าการตรวจจริง แดชบอร์ดจึงใช้ เวลาที่เร็วที่สุดของ กดเริ่มตรวจ / สั่ง Lab / สั่ง X-ray / สั่งยา / เวลาที่พยาบาลจดใน HPI (เช่น "รายงานแพทย์ at 09.15") และแสดง % ความครอบคลุมคู่กันเสมอ ประเด็นนี้ขึ้นเป็น "ข้อสังเกตด้านการบันทึก" ใน Alert ไม่ใช่เรื่องเร่งด่วน · แนะนำให้พยาบาลจด "รายงานแพทย์ at HH.MM" ใน HPI ทุกรายเพื่อให้ตัวเลขใกล้ความจริงขึ้น

เวร แบ่งตามเวลาเข้า ER — 00:00–08:00 ดึก · 08:01–16:00 เช้า · 16:01–23:59 บ่าย

8.4 รายงานพยาบาลตรวจแทนแพทย์ — ตั้งรหัสเข้าดู

รายงานนี้แสดงชื่อพยาบาลรายคน จึงควรตั้งรหัสเข้าดู (ไม่ตั้ง = ใครเปิดลิงก์ก็ดูได้) เก็บเฉพาะ hash ไม่เก็บรหัสจริง:

# 1) สร้าง hash ของรหัส (พิมพ์รหัสแล้วกด Enter)
.venv/bin/python -c "from werkzeug.security import generate_password_hash as g; print(g(input(), method='pbkdf2:sha256'))"
# 2) สุ่ม key สำหรับ cookie
.venv/bin/python -c "import secrets; print(secrets.token_hex(32))"
# 3) ใส่ใน .env (hash มีเครื่องหมาย $ ต้องครอบด้วย '...')
ER_NP_PASS_HASH='pbkdf2:sha256:...'
ER_SECRET_KEY=<ค่าที่สุ่มได้>

รีสตาร์ตบริการ · รหัสครอบทั้งหน้าเว็บ, Excel และปุ่มส่งออก · อยู่ในระบบ 12 ชั่วโมง · ใส่ผิด 10 ครั้งพัก 15 นาที · เปลี่ยนรหัส = สร้าง hash ใหม่ (ผู้ที่เข้าระบบอยู่จะต้องใส่รหัสใหม่ทันที)

ตรวจรหัสประเภทผู้ให้บริการ — พยาบาลนับจาก doctor.provider_type_code (ค่าเริ่มต้น 03) ตรวจด้วย SELECT provider_type_code, COUNT(*) FROM doctor GROUP BY 1 แล้วตั้ง ER_NURSE_PROVIDER_TYPES ถ้าโรงพยาบาลใช้รหัสอื่น

9เปิดผ่านโดเมนของโรงพยาบาล

วางใต้ sub-path เช่น https://<โดเมน>/erdash/ (Apache) — ใส่ก่อนบรรทัด catch-all ProxyPass /:

ProxyPass /erdash/ http://127.0.0.1:6200/
ProxyPassReverse /erdash/ http://127.0.0.1:6200/
<Location /erdash/>
  RequestHeader set X-Forwarded-Prefix /erdash
  RequestHeader set X-Forwarded-Proto https
</Location>
แก้ค่าตั้ง Apache ทุกครั้ง — สำรองไฟล์ → httpd -t → ผ่านค่อย systemctl reload httpd ไม่ผ่านให้คืนไฟล์สำรองทันที (เว็บอื่นบน vhost เดียวกันจะพังพร้อมกัน)

10ตรวจสอบหลังติดตั้ง

  • setup_check.py ไม่มีข้อ ✘ และหน้า /check ไม่มีข้อ “ไม่ตรง”
  • /healthz ตอบ {"status":"ok"}
  • จำนวนผู้มา ER ตรงกับรายงาน ER ของ HOSxP ในช่วงเดียวกัน
  • บล็อก 11 "มีเวลาพบแพทย์" ไม่ต่ำผิดปกติ (ถ้าต่ำ ตรวจหัวข้อ 8.1)
  • บล็อก 11 "ลงระดับ Triage" ใกล้ 100%
  • ปุ่ม ⬇ JPG ได้ไฟล์ภายใน ~15 วินาที
  • เปิดจากมือถือได้ ไม่ต้องเลื่อนข้าง

11ความปลอดภัย

  • แสดงเฉพาะตัวเลขรวม ไม่มี HN / ชื่อผู้ป่วย · ไม่แสดงจำนวนผู้เสียชีวิต
  • พารามิเตอร์และค่าตั้งทุกตัวที่ต่อเข้า SQL ถูกตรวจรูปแบบก่อน · session ฐานข้อมูลเป็น READ ONLY
  • แอปไม่มีระบบล็อกอิน — ถ้าเปิดออกอินเทอร์เน็ต ตั้ง HTTPS, rate limit, firewall ที่ proxy และพิจารณาจำกัดผู้เข้าถึง (รายละเอียดใน SECURITY.md)

13นิยามตัวชี้วัด

ตัวชี้วัดนิยาม / แหล่งข้อมูล
ผู้มา ERer_regist ที่มี enter_er_time ในช่วงวันที่ (vstdate) และ ER คัดกรองแล้ว (มีระดับความเร่งด่วนและประเภทผู้ป่วย) — เคสส่งมาผิดไม่นับทุกบล็อก
ระดับความเร่งด่วนer_emergency_level_id ถ้าว่างใช้ er_emergency_type.export_code
Trauma / จราจรมีรหัส ICD-10 กลุ่ม S/T · จราจร = กลุ่ม V
รับบริการer_pt_type = 4 (ทำแผล ฉีดยา ฯลฯ)
เวลาพบแพทย์เร็วที่สุดของ กดเริ่มตรวจ / สั่ง Lab / X-ray / ยา / เวลาที่พยาบาลจด "รายงานแพทย์" ใน HPI ภายใน 0–240 นาทีหลังเข้า ER
กลับมา ER ซ้ำ ≤ 48 ชม.มี ER visit ก่อนหน้าของ HN เดียวกันภายใน 48 ชม. ไม่นับรับบริการ มาตามนัด และโรคหลักรหัส Z ทั้งสองครั้ง
เวลาใน ERเข้า ER → ลงทะเบียน Admit (ipt) / เวลาส่งต่อแรก (referout)
ส่งมาจาก OPDovst.main_dep ไม่ใช่ ER_DEPCODE และไม่อยู่ใน ER_NOT_DEPCODES
สีแดงเกิน 60 นาทีระดับ 1 ที่ Admit/Refer และเวลาใน ER เกิน ER_RED_MAX_MIN
อุบัติเหตุหมู่ผู้บาดเจ็บสาเหตุกลุ่มเดียวกัน (ICD-10 V–Y: จราจร สัตว์/แมลง ทำร้าย สารพิษ ไฟ พลัดตก) ≥ ER_MCI_MIN รายภายใน ER_MCI_WINDOW นาที แบบหน้าต่างเลื่อน — เป็นการคัดกรองอัตโนมัติ หัวหน้า ER ควรยืนยัน
สาเหตุการบาดเจ็บรหัส V01–Y98 จัดกลุ่ม 3 หลัก ไม่นับมารับบริการต่อเนื่อง (โรคหลักเป็นรหัส Z)
พยาบาลตรวจแทนแพทย์เข้า ER 16:00:00–20:00:59 และผู้ลงโรคหลัก (ovstdiag, ถ้าว่างใช้ ovst.doctor) เป็นพยาบาล ไม่รวมงานบริการ (er_pt_type 4, โรคหลัก Z48 / Z23–Z27) ซึ่งแยกนับเป็น "พยาบาลให้บริการ" · ปีงบประมาณ ต.ค.–ก.ย. · วันหยุดจากตาราง holiday
